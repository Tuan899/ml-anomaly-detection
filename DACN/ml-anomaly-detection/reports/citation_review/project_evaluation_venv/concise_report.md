## Protocol and limitations

- Four independent synthetic CSV fixtures generated by scripts/generate_mysql_demo.py, seed 20261107. No real MySQL server was used in this evaluation; MySQL version and server configuration are not applicable.
- Every file contains 1,440 one-minute samples dated 2026-10-01 00:00-23:59. Identical first 1,008 normal rows train each model, final 432 rows test. No shuffling, separate validation partition, parameter tuning, sliding windows, or calendar features in this measured run.
- Features: queries_per_second, connections, response_time_ms, slow_queries, connection_errors. Explicit label=1 normal, label=-1 anomaly. Labels/scenario are excluded from all model features. Input validation sorted timestamps; no data rows dropped.
- StandardScaler fit once to training rows only, then transform test. MAD median/MAD, model fit, gate statistics and thresholds use training rows only.
- Raw predictions evaluate the estimator. Operational alerts additionally require a material deviation in at least one metric. These are distinct outputs and must not be mixed.
- Normal test has zero positives. Script emits P/R/F1=0 by zero_division convention; write N/A in report and discuss false positives instead. Perfect scores on easy synthetic spikes do not establish real MySQL effectiveness.
- Timings below are a single run per dataset/model using perf_counter. Train time excludes shared StandardScaler; predict time includes model.predict + decision_function. They exclude reading, validation, gate/evidence, reporting, HTTP and UI. No repeated benchmark or end-to-end latency claim.

## Model configuration

- MAD: robust z = 0.6745*(x - train_median)/train_MAD, aggregate max absolute z over five features, anomaly at >=3.5. If MAD=0, uses train-only epsilon tolerance; it is a robust Z-score baseline, not classical mean/std Z-score.
- Isolation Forest: n_estimators=100, max_samples=auto (256 samples for 1008 training rows), max_features=1.0, contamination=0.01, bootstrap=False, random_state=42.
- LOF: n_neighbors=20, contamination=0.01, novelty=True, Minkowski p=2, leaf_size=30.
- One-Class SVM: RBF kernel, nu=0.01, gamma=scale, tol=0.001, cache_size=200, max_iter=-1.
- Operational gate: raw anomaly AND any |x - train_median| > max(3.5*max(1.4826*MAD, IQR/1.349), absolute floor, 0.05*|train_median|). Absolute floors ordered by five metrics: [2.0, 2.0, 5.0, 1.0, 0.0]. This is a demonstration policy, not a MySQL SLA.

## Interpretation based on this run

- On normal data raw FP were MAD48, IF11, LOF5, SVM8, corresponding to false positive rates 11.11%, 2.55%, 1.16%, 1.85%. Gate reduced these to zero in all four methods.
- On query spikes, raw MAD/LOF/SVM recalled all44 points; IF detected none (FN44). Guard cannot recover anomalies the model missed.
- On connection spikes, IF detected2/44 (recall4.55%); LOF/SVM/MAD detected44/44. On latency spikes IF detected24/43 (recall55.81%); other three detected43/43.
- LOF, SVM and MAD each attained operational P/R/F1=100% on all three intentionally separated synthetic events. IF operational precision=100% where alerts exist, but query/connection/latency recall was 0%/4.55%/55.81%. No general claim that IF is superior is supported.
- Raw LOF F1 by query/connection/latency:94.62%/95.65%/94.51%; raw SVM:92.63%/92.63%/91.49%; raw MAD:70.97%/65.67%/64.18%. Gate policy contributes substantially to improved operational scores and must be disclosed.
- RQ1 and RQ2 can be answered within synthetic default-config scope. RQ3 (single variable vs windows/multivariate ablation) was not tested. RQ4 remains a deployment limitation, not a validated real workload result.
